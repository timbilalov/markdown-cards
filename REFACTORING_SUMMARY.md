# Краткая сводка рефакторинга Markdown Cards

1. **Разделены архитектурные слои и объединена модель данных.**

   Раньше логика заметок, хранения и синхронизации была распределена по компонентам,
   stores и DBService, типы дублировались. Теперь domain, application и адаптеры
   разделены; UI обращается к общему facade и состоянию приложения.

2. **Введён строгий версионируемый Markdown.**

   Раньше формат не имел версии, парсер допускал частичное распознавание.
   Теперь v1 проверяется целиком; неизвестный или неподдерживаемый документ
   сохраняет точный исходник и открывается с запрещённым Save.

3. **Добавлена явная миграция старых заметок.**

   Раньше отдельного сценария обновления формата не было. Теперь кнопка
   «Обновить формат» преобразует legacy-документ локально, а обычный Save
   записывает результат на Диск по прежнему имени. Для v1 кнопка скрыта.

4. **Доступ к Яндекс Диску перенесён на сервер.**

   Раньше браузер использовал OAuth-токен и прямые запросы к провайдеру.
   Теперь токен хранится в private env, запросы проходят через серверный адаптер
   с проверкой путей и ответов. Сохранение передаёт точные байты Markdown.

5. **Усилена авторизация и защита интерфейса.**

   Раньше проверки сессии и доступ к заметкам были разрозненными.
   Теперь используется подписанная серверная сессия, проверки Origin/CSRF,
   CSP и очистка preview. Без сессии закрытые страницы скрыты, logout отменяет
   дальнейшие облачные запросы, сохраняя локальные данные.

6. **Сохранение стало атомарным и сначала локальным.**

   Раньше карточка, Markdown-снимок и очередь записывались раздельно.
   Теперь одна транзакция IndexedDB сохраняет их вместе с Save ID;
   подтверждение старой отправки не удаляет новую версию. UI различает
   локальное сохранение и подтверждённую запись на Диск.

7. **Объединены правила синхронизации и повторов.**

   Раньше редактор, очередь и кеш использовали разные сценарии.
   Теперь общий CardSync и worker обрабатывают load/save/retry;
   Web Locks координирует вкладки. Конфликт и неизвестный результат записи
   сохраняют локальную версию и блокируют слепой повтор; createOnly защищает новый файл.

8. **Защищены кеш и существующие локальные данные.**

   Раньше карточки сопоставлялись по внутреннему ID, кеш мог очищаться по возрасту
   или отсутствию файла в списке. Теперь доска учитывает имя файла и локальные
   снимки, позднее чтение не затирает Save. БД обновляется до v5 без очистки старых записей.

9. **Удалён legacy и упорядочена сборка.**

   Раньше оставались старые endpoints, кодеки, очередь, helpers и несколько
   вспомогательных планов. Они удалены; закреплены Node 24/npm, исправлены
   конфигурация Vercel и генератор пароля, запуск и эксплуатация описаны в README.

10. **Добавлены проверки цельных пользовательских сценариев.**

    Раньше часть тестов описывала старые API и известные дефекты.
    Теперь unit/integration и Chromium E2E проверяют миграцию, Save,
    offline/reconnect, конфликты, потерю подтверждения и обновление БД.
    Изменения поведения проходили RED → GREEN; общая проверка включает типы, тесты и сборку.
