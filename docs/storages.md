# Хранилища

Приложение использует одно активное облачное хранилище. Остальные подключения
доступны для сравнения и ручного копирования заметок. Автоматического переключения
на резервное облако нет.

## Настройка

Задайте две private-переменные окружения. Даже для одного хранилища нужен массив:

```dotenv
CLOUD_STORAGES='[{"id":"disk","label":"Яндекс Диск","provider":"yandex","accessToken":"...","rootPath":"md-cards"},{"id":"dropbox","label":"Dropbox","provider":"dropbox","appKey":"...","appSecret":"...","refreshToken":"...","rootPath":""}]'
CLOUD_STORAGE_ACTIVE=disk
```

`CLOUD_STORAGE_ACTIVE` — ID подключения из массива. После изменения настроек
перезапустите сервер или выполните новый deploy, затем обновите открытые вкладки.
Токены и секреты остаются на сервере; не используйте префиксы `VITE_` или `PUBLIC_`.

Каждому подключению нужны уникальный `id` (латинские буквы, цифры, `_`, `-`),
произвольное название `label` и провайдер `provider`. Можно добавить несколько
подключений одного провайдера, если они ведут в разные папки или аккаунты.
Поддерживаются `yandex` и `dropbox`; папки должны существовать заранее.

## Подключение Яндекс Диска

1. Создайте OAuth-приложение по [инструкции Яндекс Диска](https://yandex.ru/dev/disk-api/doc/ru/concepts/quickstart).
   В доступах включите `cloud_api:disk.info`, `cloud_api:disk.read` и
   `cloud_api:disk.write`: информация об аккаунте, чтение и запись файлов.
2. Откройте авторизацию, подставив ClientID своего приложения вместо `CLIENT_ID`:
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=CLIENT_ID`.
   Подтвердите доступ и сохраните полученный OAuth-токен.
3. Создайте на Диске папку для заметок, например `md-cards`.
4. В подключении с `provider: "yandex"` в `CLOUD_STORAGES` заполните `accessToken`
   полученным токеном, а `rootPath` — путём папки без `disk:/`, например `md-cards`.

## Подключение Dropbox

1. Создайте **Scoped access** приложение в [Dropbox App Console](https://www.dropbox.com/developers/apps).
   Выберите **App folder** для отдельной папки приложения или **Full Dropbox**
   для доступа к существующей произвольной папке.
2. В Permissions включите `account_info.read`, `files.metadata.read`,
   `files.content.read`, `files.content.write` и сохраните настройки.
3. Откройте авторизацию, подставив App key вашего приложения вместо `APP_KEY`:
   `https://www.dropbox.com/oauth2/authorize?client_id=APP_KEY&response_type=code&token_access_type=offline`.
   Подтвердите доступ и получите одноразовый code.
4. Обменяйте code на refresh token, подставив свои значения:

   ```sh
   curl https://api.dropboxapi.com/oauth2/token \
     --data-urlencode 'grant_type=authorization_code' \
     --data-urlencode 'code=AUTHORIZATION_CODE' \
     --data-urlencode 'client_id=APP_KEY' \
     --data-urlencode 'client_secret=APP_SECRET'
   ```

   Если при авторизации использовался `redirect_uri`, передайте тот же URI при
   обмене кода. Сохраните `refresh_token` из ответа; не публикуйте ответ с токенами.
5. Заполните `appKey`, `appSecret`, `refreshToken` в `CLOUD_STORAGES`. Access token
   приложение получает и обновляет самостоятельно. Для корня App folder задайте
   `rootPath: ""`, для вложенной папки — например `/notes`.

Пути Dropbox отсчитываются от области доступа приложения: `/` в интерфейсе
означает её корень. Dropbox не различает регистр имён: `Note.md` и `note.md`
нельзя скопировать туда как две разные заметки.

## Сравнение и синхронизация

Откройте **Хранилища** в меню. Таблица показывает исходники всех настроенных
облаков и локальных кэшей, их папки, названия заметок и даты версий. Название
берётся из актуальной версии; если его определить нельзя, остаётся имя файла.
Расхождения отмечаются отдельно.

Актуальность определяется по `Modified` внутри заметки. Дата облачного файла
показана отдельно и не используется для выбора. Одинаковые тексты считаются
одной версией. Самая новая версия выделяется, если её можно определить однозначно;
ошибки чтения, неизвестный формат или разные тексты с одинаковой датой оставляют
актуальность неопределённой.

Выберите одну заметку или все, эталон и назначения, подготовьте план и выполните
синхронизацию. Эталоном может быть облако или локальный кэш, в том числе более
старая копия. Копируется точный исходник: содержимое и даты внутри документа
не меняются. Отсутствующие в эталоне файлы пропускаются, совпадающие не
переписываются; облачные файлы не удаляются.

Если исходник или назначение изменились после подготовки плана, обновите версии
и выберите направление заново. Dropbox дополнительно проверяет ревизию при записи.
У Яндекс Диска остаётся окно между проверкой и записью, поэтому на время копирования
лучше исключить редактирование тех же файлов сторонними программами.

Если результат записи неизвестен, используйте **Проверить запись**. Это проверка
состояния файла без повторной отправки. Заменяемая локальная работа сохраняется
в архиве кэша; ручная копия в локальный кэш сама по себе не отправляется в облако.

## Локальные кэши

Каждому сочетанию подключения, аккаунта и папки соответствует отдельный кэш.
После смены аккаунта или папки прежний кэш остаётся доступным для сравнения
и переноса заметок. Первым показано активное облако с его кэшами, затем остальные
облака со своими кэшами. Кэши удалённых подключений находятся в конце.

Раздел **Локальные кэши** показывает назначение кэша, число заметок, локальных
изменений и незавершённых операций. Перед удалением перенесите нужные данные.
**Удалить кэш** удаляет всю выбранную локальную базу, включая очередь и архив,
после подтверждения. Облачные файлы остаются на месте. Текущий кэш и кэши
с неподтверждённой ручной записью защищены; другая открытая вкладка может
задержать удаление до своего закрытия.

Удалённый резервный кэш появится снова при выборе этого подключения активным
или при ручной записи в соответствующее облако. Очистка данных сайта удаляет
все локальные кэши, архивы и журнал синхронизации.
